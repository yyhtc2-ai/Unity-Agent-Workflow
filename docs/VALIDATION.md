# 0.3.0 验证记录

日期：2026-11-02。测试在 Windows、Node.js 24.22.1、Codely CLI 1.0.0-nightly.71 上执行。针对本地 0.3.0 修复构建，外部模型任务限于隔离临时 Unity 格式目录中的 Node 工具，不运行 Unity Editor。账号信息、原始会话、数据库和临时工程不打包。

## 五项问题与回归

| 问题 | 修复及已执行证据 |
| --- | --- |
| P0 正文丢失 | 原生 `-p` 参数传完整策略与正文；模拟后端仅从 argv 取任务；真实会话的用户消息精确包含原始任务与策略，并正确返回随机回执 |

额外修复了真实运行中发现的 Windows EPERM：快照替换遇短暂文件占用时进行有界重试，耗尽后保留旧记录，不先删除目标文件。测试包括锁冲突注入、不可重试错误和双进程查询时的快速更新。

执行：`python scripts/verify.py`。原有 MCP 集成测试、12 项新增回归、5 项交接工具测试通过。跨平台最新结果见 GitHub Actions；真实账户测试不在默认 CI 内运行。

## 真实端到端验证

分派内容：实现只读 Unity `.meta` 完整性检查模块；允许写一个模块文件，不允许 Editor、shell、外部文件、嵌套 Agent 或视觉任务。验收材料在宿主内存中、于执行者退出后构造；随机回执只存在于下发提示中，未预先写入项目。

- CLI 正常退出，结构化 result 成功；该次 CLI 执行耗时约 241.2 秒，单样本不代表性能基准。
- 完整任务和固定策略在实际用户消息中验证通过，随机回执逐字匹配。
- 14 项行为检查通过：正常、缺失、孤立、无效和空 metadata，GUID 重复与大小写归一化、Unicode 路径、隐藏项、文件夹 metadata、缺少 Assets、组合错误、CRLF、无 metadata 的文件夹及符号链接排除；同时检查确定性及已有文件内容不变。
- 五个初始文件未改变；模型工具记录只有项目内读取和对指定模块的写入。
- CLI 自动生成会话存档及 UnityInsight 索引/锁文件，已从业务文件改动中单列。首次范围检查未识别索引缓存，修正分类后通过 `--verify-existing` 复核同一已完成会话，没有追加模型调用；原始失败记录保留，补充复核证据，不重写历史。
- 更早一次真实尝试曾因上述 EPERM 中断，修复后重新执行；不把该失败尝试计作成功。

尚未证明：完整 Unity/C# 编译、场景与 Prefab 的正确性、所有 Agent Foundry 技能行为、Mac 的真实账户和 Editor 链路、其他 CLI 版本、长期无人值守和跨机器互斥。
